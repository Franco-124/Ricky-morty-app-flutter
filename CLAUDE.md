## Architecture

This is a Flutter app (package name `second_appp`) that browses Rick & Morty characters using the public Rick and Morty REST API, with Firebase for auth and favorites persistence.

**Navigation flow:**
`LoginScreen` → `HomeScreen` (bottom nav) → `CharactersScreen` or `FavoritesScreen` → `CharacterDetailScreen`

`RegisterScreen` is reachable from `LoginScreen`.

**Key layers:**

- **Model** — `character.dart`: `Character` has two factory constructors: `fromJson` (API response, where `origin` is a nested object) and `fromFirestore` (Firestore document, where `origin` is a flat string).
- **Services** — `CharacterService` fetches paginated characters from `https://rickandmortyapi.com/api`; `FavoritesService` reads/writes to Firestore at `users/{uid}/favorites/{characterId}`, requires an authenticated user (`FirebaseAuth.instance.currentUser`).
- **Theme** — `AppTheme.darkTheme` and `AppColors` in `app_theme.dart` define the full dark theme. Always use `AppColors` constants instead of raw `Color` values.
- **Firebase** — initialized in `main()` using `firebase_options.dart` (auto-generated, do not edit manually). Auth is email/password only.

## Firebase setup

The app requires a connected Firebase project. `firebase_options.dart` is generated by the FlutterFire CLI (`flutterfire configure`) and must not be committed with real credentials for public repos. Firestore security rules must allow authenticated users to read/write their own `users/{uid}/favorites` subcollection.
